3.2 Part 3 · Foundation models for robots

Vision-language models: how an image gets into a language model

RT-1 from lesson 3.1 knows exactly as much about the world as there was in 130,000 robot demonstrations. Large language models do know about the world, but they read text, while the robot sees through a camera. In this lesson we'll work out how an image is turned into a sequence of tokens and fed into a language model. ViT cuts an image into squares of 16 × 16 pixels and makes a token out of each one. LLaVA takes a ready-made vision network from CLIP and a ready-made language model and trains a single matrix between them that maps image tokens to vectors the language model understands. PaliGemma is built the same way from open parts and has 3 billion parameters. Models that read an image together with text and answer in words are called vision-language models, or VLMs. In the lab, a small VLM trains in your browser and describes an object in two words, and a vision network trained in advance competes with one that learns from scratch.

1 Knowledge

The robot knows its demonstrations, the language model knows the world

In lesson 3.1, RT-1 picks an action as a token out of 256 bins, and it learned to do that from 130,000 demonstrations. They contain nothing beyond what people showed the robot: objects from the counters of an office kitchen and commands from a set that took 17 months to collect. Ask RT-1 to pick up an object that wasn't in the demonstrations, or to explain what a “dead screen” means, and the model has nowhere to get it from.

Large language models do know about the world. In lesson 2.3, SayCan asked a language model which step is useful for a request, Code as Policies had it write code, and VoxPoser built maps from its code. But each time the model got text and returned text, and the scene was retold to it by detectors: a list of objects, coordinates, the answer “success — no”. A detector sees only what it was trained to see, and anything outside its vocabulary never reaches the language model.

We'd like to remove the middleman and show the language model the image itself. A model that takes an image and text and answers with text is called a vision-language model, or VLM. The difficulty is that a language model reads a sequence of tokens: each token is a fixed-length vector from an embedding table, and the attention from lesson 1.6 works with such vectors. An image is a 224 × 224 × 3 grid of pixels, some 150,000 numbers with no sequence to them at all. How do you turn it into tokens that a transformer will read the same way it reads words?

🧩 Interactive 1

ViT: patches become tokens

A transformer reads a sequence of vectors of the same length, and an image is a grid of pixels. In lesson 1.6 we already cut a kitchen frame into patches to work out the cost of attention; Vision Transformer (ViT, Dosovitskiy et al., Google, 2021) builds the whole model on this slicing. A 224 × 224 image is cut into patches, squares of 16 × 16 pixels, which gives 14 × 14 = 196 patches. Each patch is flattened into a vector of 16 · 16 · 3 = 768 numbers and multiplied by one and the same trainable matrix: this is a linear layer, and it maps the patch to a vector of the model's width. The authors call the result patch embeddings, and from there an ordinary transformer from lesson 1.6 works with them: all-to-all attention, fully connected blocks, normalization. A separate trainable token at the start of the sequence, like [class] in BERT, gathers the answer for classification.

Attention doesn't know the order of tokens: shuffle them, and the output is shuffled the same way. For words, this was solved by the positional encodings from lesson 1.6, and for patches it's solved the same way: a trainable vector for the patch's position is added to each patch embedding. At the start of training, these vectors in ViT know nothing about patch 2 lying to the right of patch 1: the model learns all spatial relations from data, unlike a convolutional network, where neighborhood is built into every layer.

On the scene is a 16 × 16 icon from the table world of lesson 2.1, cut into 16 patches of 4 × 4 pixels. A linear layer maps each patch to a vector of 16 numbers, a position vector is added to it, and the 16 tokens go into a single attention block. This is the encoder, the part of the model that turns an image into vectors; the small VLM in the lab below will need it. On the right is the mean of all output tokens and its similarity to the output for the original, unshuffled image.

Under the hood: the ViT formula, model sizes and what positions gave

An image \(x \in \mathbb R^{H \times W \times C}\) is cut into \(N = HW/P^2\) patches with side \(P\); \(N\) is the sequence length. The paper writes the transformer input like this:

\[\begin{gathered} z_0 = [\,x_\text{class};\ x_p^1 E;\ x_p^2 E;\ \dots;\ x_p^N E\,] + E_\text{pos}, \\ E \in \mathbb R^{(P^2 C) \times D}, \qquad E_\text{pos} \in \mathbb R^{(N+1) \times D}. \end{gathered}\]

One matrix \(E\) for all patches, a separate row of \(E_\text{pos}\) for each position, then \(L\) identical blocks: multi-head attention and a fully connected block, each with normalization before its input and a residual connection. Three sizes from the paper: ViT-Base has 12 layers, width 768 and 86M parameters; ViT-Large has 24 layers, width 1024 and 307M; ViT-Huge has 32 layers, width 1280 and 632M. The notation ViT-L/16 means the Large model with a 16 × 16 patch; the sequence length is inversely proportional to the square of the patch side, so ViT-L/14, with a patch of 14, is more expensive than ViT-L/16.

The positional vectors in the paper are one-dimensional: 196 trainable rows, one per patch number in reading order. The authors also tried two-dimensional encodings (separately for the row and the column) and relative ones: on ImageNet with five examples per class, ViT-B/16 without positional vectors gives 0.614, with one-dimensional ones 0.642, with two-dimensional ones 0.640, and with relative ones 0.640. The gap between “no positions” and “with positions” is large, and between the ways of encoding them there is almost none. Without positions, the authors call the input a “bag of patches”.

Data mattered more than architecture. Pretrained on ImageNet with 1.3M images, ViT-Large loses to ViT-Base; on ImageNet-21k with 14M images they draw level, and only on the private JFT dataset with 303M images do the large models come into their own. ViT-H/14 after JFT reaches 88.55% on ImageNet for 2,500 TPUv3-core-days, while the ResNet BiT-L gets 87.54% for 9,900. Our encoder is tiny: a patch of 4 × 4 × 3 = 48 numbers, width 16, one block, one head, 3,200 parameters.

Once it's cut up, an image is no different from text: it's a sequence of vectors, and a transformer reads it with the same attention. Everything that follows rests on this: PerAct in lesson 2.2 cut a voxel grid into 5 × 5 × 5 patches, RT-1 in 3.1 took 81 tokens from a convolutional network, and the VLMs we're about to discuss get hundreds of image tokens from a ViT. But a language model has its own embedding table: the vector of the word “red” is a row of that table, while a patch vector is the output of someone else's network, with a different width and a different scale. How do you put them into one sequence?

2 Projector

LLaVA and PaliGemma: a projector between the encoder and the language model

Image tokens and word tokens live in different spaces: the encoder has its own width and its own meaning for the axes, and the language model has its own embedding table that all of its attention is tuned to. Training a single network from scratch that reads both would mean rebuilding both the knowledge of the world from text and vision from images.

LLaVA (Liu et al., University of Wisconsin–Madison and Microsoft Research, 2023) takes both parts ready-made. Vision is the image encoder of CLIP from lesson 2.1, in its ViT-L/14 version; its weights are frozen. Language is the Vicuna model. Between them sits a projector: a trainable matrix \(W\) that maps each output token of the encoder to a vector of the same dimension as the language model's word embeddings. After the projector, the image tokens are simply placed in the sequence before the question tokens, and the language model reads them with ordinary attention, without telling them apart from words. The authors describe this stage as training “a compatible visual tokenizer for the frozen LLM”.

Training goes in two stages. In the first, both the encoder and the language model are frozen, and only the projector is trained, on 595,000 image–caption pairs filtered from the CC3M dataset: the model learns to produce the caption from the image. In the second, the projector and the language model are fine-tuned together on instructions: 158,000 examples that a text-only GPT-4 wrote from the captions and bounding boxes of COCO images, namely 58,000 conversations, 23,000 detailed descriptions and 77,000 answers with reasoning. The encoder stays frozen throughout. All the training ran on eight A100 GPUs, and on a synthetic set of questions the result came to 85.1% of GPT-4's score; without the second stage, the ability to follow instructions dropped by more than 50 points. In LLaVA-1.5, from the same year, the linear projector was replaced with a two-layer MLP, and the encoder was taken at a resolution of 336 px.

PaliGemma (Beyer, Steiner, Pinto, Kolesnikov, Wang et al., Google DeepMind, 2024) is built the same way from open parts: the SigLIP-So400m encoder with 400M parameters, trained contrastively with a sigmoid loss, the Gemma-2B language model, and a linear projector between them initialized to zeros. In total, under 3B parameters. The image is resized to a square of 224, 448 or 896 pixels and gives 256, 1024 or 4096 tokens; they come first, followed by the beginning-of-text token, the prompt and a newline as a separator, then the answer. The attention is prefix attention: the image and prompt tokens see each other in full, in both directions, so the image can “peek” at the question, while the answer tokens are generated autoregressively and see only what comes before them. The authors also tried the ordinary causal mask from lesson 1.6, on the prompt and on the image: both work worse. The loss is computed only on the answer tokens.

Unlike LLaVA, PaliGemma freezes nothing, even in the first multimodal stage: the encoder is fine-tuned together with the language model on a billion examples at 224 px, with a slow warm-up of its learning rate so that the gradients of the not-yet-aligned language model don't ruin its features. According to the authors' ablation, after transfer to tasks there's no difference between a frozen and a trainable encoder, but on tasks about where objects are, perplexity is noticeably better without freezing; a frozen language model is much worse, and any part trained from scratch instead of starting from a ready checkpoint makes the result collapse. They compared projectors too: linear versus MLP, 77.2 versus 77.1 points with all weights trained. Then the resolution is raised to 448 on 50M examples and to 896 on 10M, and the three base models are fine-tuned for a specific task.

The recipe is the same: a ready-made encoder, a ready-made language model and a trainable bridge between them. To see what exactly happens on this bridge, let's build such a model in miniature and train it right here. Will a ready-made encoder work better than an encoder trained together with everything else?

🔬 Lab

A mini-VLM describes an image

Let's build a miniature LLaVA out of three parts, each of which trains here, in your browser. The encoder is the mini-ViT from the interactive above: 16 patches, one attention block, 3,200 parameters. We pretrain it contrastively, with the same InfoNCE objective as the mini-CLIP in lesson 2.1: the mean of the image tokens is pulled toward the sum of the vectors of the caption's two words, and mismatched pairs are pushed apart. The stream of images for pre-training covers all 24 combinations of six colors and four shapes, with 16 new images per step: that's the encoder's “internet”. The projector is a linear layer from the encoder's 16 numbers to the language model's 16 numbers, 272 parameters. The language model is a single transformer block with prefix attention, as in PaliGemma, and a vocabulary of ten words and two special tokens, 2,400 parameters; we pretrain it on caption text without images, so that it knows a shape comes after a color, and the end of the answer comes after the shape.

The VLM itself is trained on 200 images with two-word captions. There isn't a single purple cube among them: 23 combinations out of 24. Training goes as in LLaVA: first, with the encoder and the language model frozen, only the projector learns; then the projector and the language model learn together, while the encoder stays frozen. The answer is generated word by word: from the image tokens and the start token the model picks a color, from the image and the color word a shape, then the end token. The test is on new images of all 24 combinations, images that weren't in training.

Under the hood: the contrastive objective, the prefix mask and the mini-VLM loss

We pretrain the encoder on batches of \(B = 16\) pairs. Let \(u_i\) be the normalized mean of the tokens of image \(i\), \(v_j\) the normalized sum of the word vectors of caption \(j\), and \(\tau = 0.1\). The loss is symmetric, as in CLIP and in lesson 2.1:

\[ \mathcal L_\text{enc} = -\frac{1}{2B}\sum_{i=1}^{B}\Bigl[\log \frac{e^{u_i \cdot v_i/\tau}}{\sum_j e^{u_i \cdot v_j/\tau}} + \log \frac{e^{u_i \cdot v_i/\tau}}{\sum_j e^{u_j \cdot v_i/\tau}}\Bigr]. \]

The projector is a matrix \(W \in \mathbb R^{16 \times 16}\) with a bias, like \(H_v = W Z_v\) in LLaVA: the encoder tokens \(Z_v\) (16 × 16) become the image tokens \(H_v\) in the language model's space. The language model's sequence is the 16 image tokens, then \(\langle\text{bos}\rangle\), the color and the shape; the text tokens have their own positional vectors. The attention mask is a prefix mask, as in Figure 2 of PaliGemma: token \(i\) sees token \(j\) if \(j\) is an image token or \(j \le i\). The output is read through the same embedding table as the input (tied embeddings): the logit of word \(w\) at position \(t\) is the dot product of the normalized state \(h_t\) and the word vector \(e_w\). The loss is the cross-entropy over the three answer positions:

\[ \mathcal L_\text{vlm} = -\frac{1}{3}\sum_{t=1}^{3} \log \frac{e^{h_t \cdot e_{y_t}}}{\sum_{w} e^{h_t \cdot e_w}}, \qquad y = (\text{color},\ \text{shape},\ \langle\text{eos}\rangle). \]

As in LLaVA, the loss is computed only on the answer tokens; the image tokens and \(\langle\text{bos}\rangle\) predict nothing. Stage 1: only \(W\) is updated, 20 epochs over the 200 captions. Stage 2: \(W\) and the language model, 80 epochs. The optimizer is Adam with a batch size of 10. The model with an encoder from scratch starts from the same initial weights of the projector and the language model and trains on the same captions for the same 80 epochs, but its encoder is random and trains together with everything else.

The same in every browser. All the numbers on the scene are computed afresh on every run and come out the same: the random seeds are fixed, and the engine computes the exponential, the logarithm, the hyperbolic tangent and the powers in Adam itself, with additions, multiplications and divisions. The built-in Math.exp and Math.pow in Chrome and Safari sometimes differ in the last digit, and training the encoder from scratch inflates such a difference about tenfold per epoch, so by the end the model gives different answers.

Ten seeds. The lab uses a single seed, 9. On seeds 1–10, the pretrained model is right on new images in 82–98% of cases and the model with an encoder from scratch in 60–87%, and the pretrained one is more accurate on every seed, by 5–32 points. The from-scratch model learns unstably: with seed 9, its training accuracy over the last ten epochs jumps between 82 and 97%, and if you change the learning rate by one part in a trillion, it scores anywhere from 78 to 90% on the test. The from-scratch model never once described the purple cube correctly. Neither did the pretrained one on seven seeds out of ten; on the other three it got it right in 1–3 images out of 8, and on nine seeds its most frequent answer is “purple ball”.

After a short joint training, three parts trained separately answer in words about an image that none of them has seen before. And the projector is just a 16 × 16 matrix; in LLaVA it's a single matrix too. What exactly does this matrix do with the image tokens, if in the first stage the language model is frozen and doesn't change its word embeddings?

🧩 Interactive 2

The projector: what changes in word space

In LLaVA's first stage the language model is frozen: its embedding table, attention and fully connected blocks don't change, and only the projector matrix learns. The authors write that this aligns the image tokens with the word embeddings, and they call the projector a visual tokenizer. Let's see what that means in our mini-VLM: take the space of its language model, 16 numbers, and project three kinds of vectors onto two principal axes, the two directions along which the vectors differ the most. The words are the ten rows of the embedding table. The model's readout is its state at the last position before it picks a word: it's the dot product of this state with the word vectors that gives the probabilities, so the readout has to lie closest to the word the model will name. And the image tokens themselves after the projector: for each of the 24 images, their mean.

The left panel always shows the state before the projector is trained: the matrix is random, and the language model has been trained only on text. The right panel shows the state after the first stage, when only the projector learned, or after the second, when the language model was fine-tuned too. The axes are shared by both panels.

A map of the language model's space: vectors of 16 numbers projected onto two principal axes. The axes have no units: distances and directions are what matter; the axes are shared by both panels, and the label at the bottom of a panel says what share of the vectors' spread they show. Labeled rings are color words, labeled squares are shape words, and the small markers are the 24 images: a marker's color is the object's color, and its shape is the object's shape. Under the hood: how the axes are computed and why the readout has to be near a word

The two principal axes are computed from the covariance of a set of 10 word vectors and 24 readouts before the color after the second stage; all three kinds of points on both panels are projected onto the same axes, so the panels can be compared. The logit of word \(w\) at position \(t\) is \(h_t \cdot e_w\), and softmax picks the word with the largest dot product. The readout \(h_t\) is normalized, so “closest by dot product” almost coincides with “closest by angle”; on the plane of the two axes this shows only approximately, since part of the distance stays in the other 14 dimensions.

Image tokens have no such obligation. Nobody compares them with words directly: they enter attention as keys and values, and the language model decides for itself what to take from them. So the alignment done by the projector in LLaVA doesn't mean that an image token becomes similar to the vector of some word. It means that the frozen language model starts extracting from these tokens what it needs for the answer. In the PaliGemma paper the projector is initialized to zeros: at the start of training the image tokens are zero vectors, and the language model sees nothing until the projector starts filling them in.

The projector maps image tokens not into words but into vectors from which the language model can assemble a word. That's the bridge between the two ready-made parts: the better the encoder and the more captions there are, the better the bridge is learned. 3 The image's path

From pixels to an answer in words

Let's put together everything from this lesson. The image is cut into patches, a linear layer with positional vectors turns the patches into tokens, the encoder passes them through its attention blocks, the projector maps the encoder outputs to the language model's width, the tokens of the text prompt line up after them, and the language model reads it all as one sequence: the image and prompt tokens in full, as in PaliGemma's prefix attention, and the answer word by word. In PaliGemma at 224 px, that's 256 image tokens per frame; in RT-1 from lesson 3.1, a frame gave 81 tokens, and TokenLearner kept 8.

What matters for a robot is that nothing on this path knows only about words: the language model's answer can be any token from its vocabulary. Teach it to output not words but action tokens after an image and a command, the way RT-1 output bins, and you get a model that goes straight from pixels and words to actions. What of the VLM design lives on in the systems of 2025–2026?

4 Today

VLMs inside the robots of 2026

The “encoder, projector, language model” recipe has become the basis of almost all the models in Part 3. π0 (Physical Intelligence, 2024) takes PaliGemma whole as a 3B-parameter backbone and adds a 300M action expert to it, 3.3B in total; the authors write that they chose PaliGemma for its openness and small size, which matters for real-time control, and that any pretrained VLM would have done. π0.5 (2025) keeps the same backbone. OpenVLA (2024) is built on the Prismatic-7B VLM: a two-part encoder, SigLIP and DINOv2, a two-layer MLP projector and the 7B Llama 2 language model, and Prismatic itself is fine-tuned on the LLaVA-1.5 dataset. GR00T N1 (NVIDIA, 2025) reads the scene through the Eagle-2 VLM with a SigLIP-2 encoder: a 224 × 224 frame gives 64 image tokens. Gemini Robotics (Google DeepMind, 2025) is built on Gemini 2.0, a general-purpose VLM to which the authors added reasoning about the physical world.

SigLIP, a contrastively trained encoder of the CLIP family, is almost everywhere; the debates are about whether to freeze the encoder (LLaVA: yes, PaliGemma: no) and how many image tokens to keep: 256 per frame in PaliGemma and π0, 64 in GR00T N1. The more tokens, the more detail is visible and the more expensive each control step becomes: the same trade-off RT-1 resolved with TokenLearner.

The first model that taught a VLM to output actions was RT-2: it took the ready-made PaLI-X and PaLM-E and fine-tuned them on robot demonstrations together with data from the internet. How actions become tokens of a language model, and what carries over from the internet to the robot along the way, is the subject of the next lesson.

5 Check yourself

Eight common misconceptions

6 Takeaways

Lesson takeaways

  1. An image is turned into a sequence just like text: ViT cuts it into 16 × 16 patches, a single linear layer makes a vector out of each patch, a position vector is added to it, and from there an ordinary transformer takes over. Without positions, the input is a bag of patches.
  2. Image tokens and words live in different spaces. The projector (a single matrix in LLaVA, a two-layer MLP in LLaVA-1.5 and OpenVLA, a zero-initialized linear layer in PaliGemma) maps the encoder outputs to the language model's width, and the model reads them as part of the sequence.
  3. Ready-made parts are cheaper than new ones. LLaVA keeps the CLIP encoder frozen and, in two stages on 595,000 captions and 158,000 instructions from GPT-4, trains the projector and then the projector together with the language model; in our lab, the pretrained encoder is more accurate on the same 200 captions than an encoder trained from scratch.
  4. PaliGemma is assembled from SigLIP-So400m and Gemma-2B: under 3B parameters, 256 image tokens at 224 px and 4096 at 896. The attention is prefix attention: the image and the prompt see each other in full, and the answer is generated autoregressively. Nothing is frozen, and that's no worse after transfer, and better on tasks about where objects are.
  5. A language model answers from the image and from habit at the same time. Our mini-VLM called the purple cube a ball because in the captions “purple” was never followed by “cube”, even though the encoder saw the cube; LLaVA likewise answered “yes” about strawberry-flavored yogurt. Caption diversity is as much a part of the model as its weights.
  6. The output of a language model can be any token in its vocabulary. That opens the way to models that take an image and a command and output action tokens: to RT-2 in lesson 3.3.

Open questions

After the projector, the image tokens don't lie near the word vectors. Does that mean the projector can be trained any old way, as long as the answers are right?

No: the space the projector puts the image tokens into determines what the frozen language model will be able to extract from them with its attention. In LLaVA, the first stage trains the projector on captions with the model frozen, and the authors note that without the second stage, where the language model is fine-tuned too, instruction-following quality drops by more than 50 points. PaliGemma goes further and freezes nothing, and it initializes the projector to zeros so that at the start of training the language model doesn't get random noise instead of an image. What remains open is how many tokens, and how wide, an image really needs: PaliGemma takes 256 per frame, GR00T N1 keeps 64.

The encoder is frozen in LLaVA and trained in PaliGemma. Which should a robot use?

PaliGemma's ablation says there's no difference after transfer to tasks, while on tasks about where objects are, a trainable encoder gives better perplexity, and for a robot the position of objects is exactly what matters. But a trainable encoder needs a learning-rate warm-up and a lot of data; otherwise the gradients from a not-yet-aligned language model spoil its features, which is just what our model with an encoder from scratch shows on 200 captions. OpenVLA instead adds a second encoder, DINOv2, to SigLIP for the sake of positional features. Which path wins with robot data, of which there's never enough, is a question for Part 4.
